# Secrets

Nothing in this repository contains a credential, and the `.gitignore` refuses
`.env`, `secrets/`, `*token*.json` and `*credentials*.json`.

## Where each secret lives

| Secret | Local | Cloud |
| --- | --- | --- |
| Vertex AI access | `gcloud auth application-default login` | Cloud Run service account |
| Gemini API key (alternative) | `VDS_GEMINI_API_KEY` in `.env` | Secret Manager |
| Gmail OAuth token | `secrets/gmail_token.json`, mode 600 | Secret Manager, mounted |
| Maps / Search / YouTube keys | `.env` | Secret Manager |
| Pub/Sub push token | `.env` | Secret Manager, generated by OpenTofu |

## What reaches the browser

Nothing. The console calls its own origin and Next.js proxies to the API
server-side (`frontend/next.config.mjs`), so no key, token or service-account
identity is ever present in client JavaScript.

## Two locks on the ingress endpoints

`/events/pubsub`, `/events/task` and `/webhooks/gmail` are protected by an OIDC
identity that Pub/Sub and Cloud Tasks present (enforced by Cloud Run IAM) *and*
by a shared secret header checked in `app/api/deps.py`. The second lock is what
still works when a demo deployment is deliberately made public so a judge can
open the link.

## Rotating the push token

```bash
cd terraform
tofu taint random_password.push_token
tofu plan && tofu apply
```

Cloud Run picks up `latest` on the next revision.
